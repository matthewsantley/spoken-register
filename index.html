Where the names actually live

  
In register.json, alongside this page. That file is the record. This page reads it and displays it; it never recalculates a name that has already been issued. Names are added by running issue.py add "TOI-2109 b" Cyg "ultra-hot giant", which writes the result to the file once and stops.

  
Why not just generate them on page load

  
Because the result would depend on the pool. Insert a word in the middle rather than appending it and every name shifts, silently, everywhere. Hashing decides a name once; after that the file is the authority and the hash is history.

  
How to contribute

  
Preview above, then open a pull request adding the line to register.json. Run issue.py check first — it catches duplicate identifiers, unknown constellations and collisions.

  
On the word pool

  
Assembled from reference sources and not yet checked by native speakers. Every entry carries a vouched_by field that is currently empty. A word that means star in a dictionary can mean something regrettable in a neighbouring dialect, and only speakers catch that. Treat the pool as unvetted until those fields fill in.
